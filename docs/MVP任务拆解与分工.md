## 0. 总体结构与共同机制

| 任务系列 | 承担方 | 一句话定位 |
|---|---|---|
| **系列 1 · 前端 + apiserver** | 本人 | 平台统一入口与数据枢纽 |
| **系列 2 · Agent 集群（Python）** | 工程师 A | 可运行的多专家对话服务 |
| **系列 3 · 数据与集成** | 工程师 B | 库表编排基座 + 旧系统防腐 + 外采接入 |

**共同机制：契约优先 + 共享样品库。**

全部接口契约已在 v1.1 文档定死，无需等待任何一方：

| 契约 | 出处 |
|---|---|
| Go↔Python 内部 API 四组（tools/data、sessions/turns/trace/checkpoints、tasks、wake） | 架构文档 §3.5 |
| SSE 六类事件（thought/token/card/progress/done/error） | 执行框架 §9 |
| 卡片 JSON（5 种 MVP 卡片信封 + payload） | 卡片协议 v1.1 |
| MVP 工具清单（8 个 builtin，输入输出语义） | 工具注册表 §8 |
| DIAG_TASK 状态机与 task_event 流水 | 架构文档 §5.6.2 |
| 指标白名单与映射表结构 | 架构文档 §4.4 |

由 **2.1 固化为 `contracts/` 目录下的 JSON fixtures + Schema 校验脚本**（进 CI）。三个系列各自对 fixtures 开发与自测，**集成 = 换 base URL / 注入实现，不改代码**（与前端已验证的 MockProvider/mockAgent 替换模式同构）。

**纪律：任何契约变更必须先改 fixture 并三方会签，再改实现**（架构 §3.3 契约治理）。

## 1. 任务系列 1：前端 + apiserver（本人）

**系列目标**：平台统一入口与数据枢纽——大盘真实数据、chat 全链路（SSE 透传 / 会话档案 / 任务调度）、内部数据 API。

**依赖项**：

| 类型 | 依赖 | 时点 |
|---|---|---|
| 开工前置 | 3.1 PG Schema | W2 前 |
| 开工前置 | 2.1 契约 fixtures | W2 前 |
| 中途依赖 | 3.2 适配器包注入 | W6 |
| 中途依赖 | 2.2 agentcluster 服务 | W6（集成①） |
| 无阻塞自研 | 全部小任务先对 fixtures 桩开发 | — |

**系列验收条件（出口）**：
1. 北极星场景全链路真实跑通（大盘发现异常 → chat 发起诊断 → 证据采集 → 异步任务 → 报告卡 → 追问）；
2. 前端 mock→真实切换仅改 Provider 配置，页面零改动；
3. docker compose 一键拉起、四容器健康检查全绿。

**小任务**：

| # | 小任务 | 排期 | 内容 | 验收标准 |
|---|---|---|---|---|
| 1.1 | 骨架与契约桩 | W1-2 | Go 工程规范/配置/日志/REST 框架；内部 API 与 SSE 的 fixtures 桩 | 桩接口对 `contracts/` 回放自测通过；`/healthz` 就绪 |
| 1.2 | 会话与档案服务 | W3-4 | sessions/turns/trace/checkpoints 四组内部 API + PG 读写 | 请求响应对与 fixtures 一致；checkpoint 存取往返一致 |
| 1.3 | 内部工具数据 API | W3-5 | `POST /internal/tools/data` + Probe Executor 通道 a/b/c 路由 + 指标查询代理与缓存 | 8 个 builtin 工具 fixtures 输入→标准化输出一致；缓存命中率有日志 |
| 1.4 | 任务总线调度 | W5-6 | DIAG_TASK 状态机 + 轮询 + task_event 流水 + wake 回调触发 | 状态迁移与 `contracts/tasks` 一致；重启恢复（pending 重调度、running 对账改判）测试通过 |
| 1.5 | chat 对外 API + SSE 透传 | W6 | 对接 agentcluster，last_event_id 断线重放 | 集成①：与系列 2 双端 fixtures 回放一致 |
| 1.6 | 元数据/告警同步编排 | W4-6 | 同步水位/幂等/Issue 化（适配器为 3.2 交付的包，先用 mock 包开发） | 水位推进与断点续传测试通过 |
| 1.7 | 前端切换与联调 | W7-10 | ApiProvider 指向真实接口、mockAgent 替换真实 SSE、权限桩/敏感过滤回归 | 集成②③通过；卡片渲染器对真实卡片流零改动 |
| 1.8 | Compose 验收与交付 | W11-12 | 编排串联（用 3.1 的 compose）、部署文档、北极星演示 | MVP 计划 §6 北极星场景 + 一键拉起 |

## 2. 任务系列 2：Agent 集群（工程师 A · Python）

**系列目标**：可运行的多专家对话服务——运行时基座 + 路由/诊断/问数专家 + 任务续聊闭环。

**依赖项**：

| 类型 | 依赖 | 时点 |
|---|---|---|
| 开工前置 | 公司 AI 平台任一 OpenAI 兼容端点（模型名配置化，未定名不阻塞） | W3 |
| 开工前置 | 本人内部 API 契约（以 fixtures 形式消费，**不依赖本人进度**） | W3 |
| 中途依赖 | 真实内部 API（仅集成① W6 需要） | W6 |

**系列验收条件（出口）**：
1. 诊断/问数两类会话对 fixtures 回放与真实链路行为一致；
2. 专家无状态——2 副本 50 并发无轮次串扰、checkpoint 中断可续跑；
3. 单容器 30s healthz 通过、护栏全开不崩溃。

**小任务**：

| # | 小任务 | 排期 | 内容 | 验收标准 |
|---|---|---|---|---|
| 2.1 | 契约样品库（牵头） | W2-3 | SSE 事件流录制、5 种卡片样例（streaming/final 两态）、内部 API 请求响应对、任务状态迁移 fixtures + Schema 校验脚本 | `contracts/validate.sh` 全绿进 CI |
| 2.2 | Agent 运行时基座 | W3-6 | LangGraph 四端口封装（执行框架 §14 映射）、AgentDefinition 加载热载、流式事件转换、护栏、wake 入口；对 fixtures mock 开发，不含业务专家 | pytest 事件序列回放一致（card_id 幂等 / last_event_id 重放）；真实 LLM 冒烟流式正常；checkpoint 中断后 wake 续跑；护栏（步数/循环熔断/敏感开关）生效；单容器 healthz 30s 通过 |
| 2.3 | 路由+诊断专家+任务续聊 | W5-8（前置 2.2） | router + diagnosis_expert + 8 工具绑定（工具注册表 §8）+ 异步任务唤醒二次推理（执行框架 §7）+ 诊断报告卡；新 fixture 回填样品库 | 诊断事件流与 fixture 全序一致（thought×3 → metric_chart → data_table → task_progress → diagnosis_report → done）；wake 链路契约测试；真实 LLM 路由准确率 ≥80%（20 问人工抽检） |
| 2.4 | 问数专家 | W9-10（前置 2.3） | 四类白名单（metrics/alert/slow_sql/topology）NL2Metric，越界明确拒答 | 3 类典型问数 fixture 一致；越界问题 100% 拒答并说明边界；工具选择率 ≥80% |

## 3. 任务系列 3：数据与集成（工程师 B）

**系列目标**：库表与部署基座 + 旧系统防腐适配 + 外采诊断接入。

**依赖项**：

| 类型 | 依赖 | 时点 |
|---|---|---|
| 开工前置 | 契约文档（已具备）；3.1 无外部依赖，即刻开工 | W1 |
| 中途依赖 | 网络连通性确认（W1，阻塞 3.2 联调，不阻塞对样例开发）；旧监控/DBaaS/告警 API 文档 | W3 |
| 外部依赖 | 外采诊断 API 契约（行动项即刻发出索取，周会跟踪） | 契约到手后 1 周内完成工程 |

**系列验收条件（出口）**：
1. 迁移幂等可重放、compose 四容器健康；
2. 三个适配器对样例响应归一化单测全绿、被 apiserver 注入即用；
3. 外采适配器（若契约到位）shadow→active 验收通过。

**小任务**：

| # | 小任务 | 排期 | 内容 | 验收标准 |
|---|---|---|---|---|
| 3.1 | PG Schema + 部署编排 | W1-2 | `deploy/db` 全量迁移（对齐架构 §6 ER：元数据 / Issue / 会话轨迹 / DIAG_TASK / task_event / 指标映射 / 缓存表）+ 指标白名单 seed（§4.4 清单）+ 四容器 docker-compose + 表↔ER 对照说明 | 迁移幂等两遍无差异；`docker compose up` 后 healthcheck 全绿；对照走查表评审通过 |
| 3.2 | 旧系统适配器 | W3-6 | metrics / dbaas / alert 三个独立 Go 包（接口契约由本人提供并评审），只输出归一化结构与领域事件，不写存储不碰业务（架构 §3.3） | 对脱敏样例响应的归一化单测全绿；限流/重试/水位语义符合架构 §9；`go vet` 干净 |
| 3.3 | 外采契约跟进 + vendor 适配器 | 行动项即刻；工程为契约到手后 1 周 | ① 非工程行动项：向供应商索取 API 文档并安全评审（鉴权/限流/数据出域），周会跟踪；② 工程：按工具注册表 §9 实现 submit/poll/normalize 三段式适配器 + ID 映射，shadow 注册，验收后转 active | 对模拟外采响应的三态轮询/超时/归一化断言全绿；诊断能力不依赖它（自建工具集兜底） |
